# 分镜规划参数与自动修正

> **当前状态（2026-10-03）：** 本计划中的强制自动预规划流程未作为当前分镜生成主流程。按用户确认，当前入口恢复 `1.3.0-preview.20261003` 单次直接规划方式；保留本文件作为历史设计和验收记录。当前源码版本 `1.4.0-preview.20261003.1` 的行为见根目录《源码交付说明》。

授权：按已讨论方案执行，不修改其他已确定功能。范围限分镜生成请求、长段规划、规划报告及对应测试。

## 约束与验收
- 页面参数在任务创建时冻结；自动数量/总时长只是参考，人工要求参与预算校验；target/capacity 不互换。
- 多场景、多段规划保留原文；对白最低可执行时间由程序复核；反应可由回答或动作承担，关联必须有因果依据。
- 最多两轮定向修正，不无限调用；结构错误分阶段报告，失败保留旧分镜。视频 Skill 仍在逐镜润色。
- P4 能力 UI、资产规则、视频提交/回传/合成协议均不改动。

## 依赖与步骤
1. FilmCreate 三个生成入口 → routes/drama.generateStoryboard → dramaService → episodeStoryboardService：传递完整来源标记和任务设置；HTTP 测试捕获漏参，旧入口兼容元数据默认值。
2. narrativeUnitPlanner：原文语义片段、事件梳理、程序计时、单元分配、汇总校验及两轮修正；旧计划读取兼容。
3. NarrativePlanReport：冻结设置、阶段/修正次数、问题与未计算值；新增纯格式化测试和真实页面检查。
4. 全量后端/前端回归、构建；隔离数据库中的多剧本/不同排版验收；真实文字模型规划按既有配置测试，不能覆盖正式分镜，不生成图片/视频。
5. 无活动任务后部署新版后端；检查接口、数据库与页面。若无法验证，明确记录，不伪报成功。

## 风险与回退
无新增依赖、无DDL、无历史数据批量改写。规划表沿用 payload 保存版本2报告和尝试记录。源码原件在工作区 .local/planner-fix-backup-20261003；测试使用内存/隔离库。用户同时编辑剧本/规则时保留已有发布前校验；修正按原事件ID合并并重新检查全局覆盖。

## 本次实现的边界
- 正式剧本、旧分镜、资产Skill、视频Skill安装与作用位置、会员管理器提交回传合成未改动；未新增能力校验门槛。
- 手动数量/总时长不满足时提供冲突；自动估算可随自然分段变化。约30秒仍是规划偏好，不得用无功能等待凑30秒。
- 当前正式视频配置仍为fixed[15,30]。自然26秒不能直接请求30秒；须在规划阶段合理重组已有事件或安排有依据的表演节奏。没有把配置偷偷改成4～30范围。
- 最多两轮自动修正是每次任务总上限，不是每阶段各两轮。失败草稿保存在报告，不覆盖旧分镜；不承诺任意脚本与冲突设置必然通过。
